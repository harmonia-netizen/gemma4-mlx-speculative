# Template Draft v14 実験録

## 目的
v13で fast path + restore fallback による推論エンジンの高速化・安全性の基礎が成立したため、v14では **推論ロジックの本体は維持しつつ、テンプレート候補の提供(provider)を拡張可能なアーキテクチャに分離すること** を目的とする。

## v14 成果
1. **Candidate Provider の導入**
   - 従来ハードコードされていた `template_draft_text(user_prompt)` を、`draft_candidates(user_prompt)`（リストを返す）と `select_candidate(user_prompt, candidates)`（1つを選択する）に分離・置換した。
2. **外れやすい候補の抑制**
   - `medium_pytest_plan` のような、候補が途中から外れてしまうケースに対しては、あらかじめ候補を出力しない(`candidates = []`)ように設定した。
   - これにより、`medium_pytest_plan` において `restore_full` に伴う不要なキャッシュ復元・再推論のオーバーヘッドがなくなり、Greedy 同等の速度 (speedup: ~1.0x) で推論可能となった。
3. **完全一致時の高速パス維持**
   - `exact_pytest_plan` においては、完全一致する候補を引き続き供給し、v13同等（約2.2倍）の高速化 (`speedup: 2.22x`) を達成・維持できた。

## 今後の課題 (v15以降)
候補提供のインターフェースができたことで、今後は以下のような発展的課題に取り組む基盤が整った。

- **複数候補の選択 (Multiple Candidates)**
  - 現在は `select_candidate` が `candidates[0]` を返しているのみだが、今後はトークンの完全一致だけでなく、信頼度 (Confidence) に基づいて最も適した候補を選択する仕組み。
- **Gating と Confidence**
  - 候補の提供にスコアを持たせ、スコアが低いものは Greedy フォールバックに任せる (今回手動でやった抑制処理の自動化)。
- **プロンプト分類**
  - プロンプトの種別（テストエラー解析、git系、コード修正等）を分類し、より的確なテンプレートセットを呼び出す。
- **実運用候補セットの設計**
  - ローカル常駐エージェントが実際に多用するコマンドやパターンセットを抽出し、事前計算されたテンプレートとして組み込む。
